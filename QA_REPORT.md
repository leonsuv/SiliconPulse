# QA report

## Overlay mode

### Visual render pass

Rendered PNG contact sheets for List, Compact, and Bar layouts at 80%, 100%, and 160% scale in English and German. Also rendered the `none` background style in both languages. Each contact sheet includes white, mid-grey, black, and busy gradient/circle backdrops. Images are available in `/tmp/SiliconPulseOverlayQA/` (for example `list_100_en.png`, `list_100_de.png`, `bar_100_en.png`, `compact_80_de.png`, `list_160_de.png`, and `none_100_de.png`). I inspected representative images from every layout, both languages, and small/large scales.

- Rows kept a consistent height; values and sparklines occupied separate fixed columns. Sparklines rendered as unfilled strokes. No overlap or clipping was visible in the inspected samples.
- German rendering showed translated hints and overlay labels, including “Batterie”, “Batterieleistung”, and “CPU-Temperatur”. OCR of the German render did not find hard-coded English UI copy; CPU/GPU/RAM and SF Symbol-adjacent abbreviations are intentionally technical labels.
- Decimal formatting followed locale conventions (comma in German, period in English).
- The `none` style showed text with a soft shadow and no pill; the default style showed the translucent dark pill without a border.

The backgrounds are synthetic test backdrops, not captured wallpaper photographs. PNGs are generated by the app's hidden `--overlay-qa-render` mode.

### Contrast measurements

Pixel sampling compared a rendered white text/value edge against its nearby backdrop. Approximate measured ratios:

| Style / backdrop | Contrast |
| --- | ---: |
| Subtle 35% dark pill / white | 1.92:1 |
| Subtle 35% dark pill / mid-grey | 4.41:1 |
| Subtle 35% dark pill / black | 13.34:1 |
| Subtle 35% dark pill / busy gradient | 2.44:1 |
| None / white | 1.05:1 |
| None / mid-grey | 2.32:1 |
| None / black | 13.45:1 |

The requested 4.5:1 threshold is not met on white and busy backgrounds for the subtle pill, nor on white and mid-grey for `none`. The specified 35% black pill and shadow-only `none` treatment cannot guarantee 4.5:1 over arbitrary bright desktop pixels. This is a measured accessibility limitation, not a passing result.

### Runtime checks

- Relaunched with the overlay preference active and observed the panel on-screen at layer 1000 at its saved 360 × 174 frame. After restoring the prior QA preferences, stopped the QA app process.
- `CGEvent`/System Events interaction testing was blocked because Accessibility trust was unavailable (`AXIsProcessTrusted() == false`) and the System Events automation request did not complete. Consequently, click-through, synthetic hotkey, Escape, Settings interaction, and Space/full-screen transitions were not independently exercised by UI automation. The overlay window is configured to ignore mouse events; pinned-panel persistence across deactivation is a separate panel behavior.
- Three-minute isolated process run: RSS ranged about 113–139 MB without sustained growth. CPU samples varied from 0–5% (several samples around 2–5%), so the earlier <1% target was not met. `CPU temperature`/HID sensor sampling was reduced to every three seconds, but further profiling is needed.
- No new crash report was observed during this QA run. The test host runs macOS 27; this pass does not validate older supported macOS versions.
